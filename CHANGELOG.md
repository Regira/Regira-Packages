# Changelog

Release summary for the Regira NuGet packages — newest first. Every change that ships in a package
adds one bullet under **Unreleased** in the same change (format: `` `PackageId` x.y.z — summary ``),
and leaves that package's `<Version>` higher than its last published version. At publish time the
Unreleased block becomes a dated release heading.

## Unreleased

- `Regira.TreeList` 6.2.0 — **behaviour change:** `OrderByHierarchy(keySelector)` sorts the roots and the children of every node by the key, level by level, as the README always described. It applied one `OrderBy` to each root's whole flattened offspring instead, so a grandchild could be emitted before its own parent and any indentation driven by `Level` came out corrupted. The parameterless overload is unchanged (pre-order, insertion order within a level); callers who relied on the flat ordering should sort the flat list themselves.
- `Regira.TreeList` 6.2.0 — **behaviour change:** the parents-selector builds (`Fill(values, getParent)`, `Fill(values, getParents)` and the `ToTreeList` overloads on top of them) now throw `InvalidChildException<T>` when input values remain that no root can reach — they take part in a cycle, or their parent object is missing from the collection — instead of silently leaving them out of the tree. They derive the roots from the values without a parent and then only walk downwards, so a cyclic value (every member of a cycle has a parent) was never visited and `ThrowOnError` never engaged: the throw the README documented did not happen on this path. `ThrowOnError = false` keeps the silent skip. A value with several parents still occupies one node per parent, which is not a cycle and is not reported.
- `Regira.TreeList` 6.2.0 — **source-breaking:** `TreeNode<T>.AddChild` returns `TreeNode<T>?`. Under `ThrowOnError = false` — the silent-skip mode the option promises — it threw `InvalidOperationException: Sequence contains no elements` instead of skipping, because it read `.First()` off the empty result of a rejected `AddChildren`. It now returns `null` like `TreeList<T>.AddValue` always did, and the children-selector fill skips the rejected subtree rather than following it. Consumers under `<Nullable>enable</Nullable>` that pass the result on will see a nullable warning at the call site.

## 6.1.3 — 2026-08-26

- All packages — version aligned at 6.1.3 for a whole-family publish. Ten packages carry a change of their own: `Regira.Entities`, `Regira.Entities.EFcore`, `Regira.Setup` and `Regira.Security.Authentication.Web` below, plus the six dependency moves at the end of this block. `Regira.Web` 6.1.3 is a comment-only clarification in `ControllerExtensions.File` — the 404-before-headers behaviour it describes shipped in 6.1.2 and is unchanged. The remaining packages are republished unchanged so the family shares one version.
- `Regira.Entities.EFcore` 6.1.3 — the attachment file-name filters built their SQL `LIKE` patterns from the **normalized** keyword but compared them against the raw `FileName` column: the default normalizer drops `.` and turns `-` into a space, so `?fileName=my-report*` searched `my report%` and matched nothing. `Extension` was worse — it interpolated the *input* wildcard into the pattern (`*pdf`) instead of SQL's `%`, an exact match on a file literally named `*pdf`. Both now build from the raw keyword minus its wildcards, in `AttachmentFilteredQueryBuilder`, `EntityAttachmentFilteredQueryBuilder` and the `EntityAttachmentQueryExtensions.Filter` extension; exact (wildcard-free) matching is unchanged. `Extension` is now anchored on the separating dot, so `?extension=pdf` matches `report.pdf` but not `handbook-nopdf` — strictly a gain against 6.1.2, where it matched nothing at all. Because the file name reaches the pattern verbatim, a `%` or `_` in a search value keeps its SQL `LIKE` meaning (`?fileName=my_report*` matches `my-report.pdf`): it over-matches, never under-matches, and is not injection — EF parameterizes the pattern. File-name filtering only, not filter parity — `EntityAttachmentFilteredQueryBuilder` still implements `ObjectId` and `FileName` alone.
- `Regira.Entities.EFcore` 6.1.3 — **behaviour change:** `QueryExtensions.FilterQ`'s explicit-fields overload now matches `QKeyword.TrimmedQW` instead of `QW` — the raw keyword, not the normalized one. It serves entities that are *not* `IHasNormalizedContent`, so the columns a caller names hold the client's value verbatim; against the normalized pattern `?q=ORD-2024-001` searched `%ORD 2024 001%` and matched nothing, while plain alphanumeric terms worked — a silent, punctuation-shaped failure. The `ParsedKeywordCollection` overload for `IHasNormalizedContent` is unchanged. A caller who pointed this overload at a *normalized* column must now build that predicate with `QW` itself; the XML doc and `entities.instructions` say so where they used to advise preferring normalized columns.
- `Regira.Entities` 6.1.3 — `QKeyword` gains a **raw** keyword family: `TrimmedStartsWith`, `TrimmedEndsWith`, `TrimmedQ` and `TrimmedQW`, completing the raw side against the existing `Trimmed`. They hold the same patterns as `StartsWith`/`EndsWith`/`Q`/`QW` but built from the trimmed input rather than the normalized one, for `LIKE`s against a column that stores the client's value verbatim (a file name, a reference code). The existing members are unchanged: everything without the `Trimmed` prefix is normalized, as `Q`/`QW` always were. Matching a family to the wrong column compiles and silently matches nothing, so `QKeyword` now documents the split on the type itself.
- `Regira.Entities` 6.1.3 — the *Match the keyword family to the column* callouts in `entities.instructions` and `entities.signatures` claimed the default normalizer **upper-cases**, offering `my-report.pdf` → `MY REPORTPDF` as the worked example. It does not: `NormalizeOptions.Transform` defaults to `NoChanges` and the registered `DefaultNormalizer` is built from it, so case is preserved and the real lookup value is `my reportpdf` — as the same file's normalize-contract table said 58 lines earlier. An agent reading the old text would write `.ToUpper()` into a normalized-column comparison and reintroduce the exact silent no-match the callout exists to prevent. Both callouts now also carry the `%`/`_` consequence of the raw `Trimmed*` family that the `Regira.Entities.EFcore` entry above spells out, so it is stated where a consumer wiring `TrimmedQW` into their own filter will meet it.
- `Regira.Entities` 6.1.3 — `entities.setup` names the `Microsoft.AspNetCore.OpenApi` floor `Regira.Security.Authentication.Web` sets (`10.0.11`) and the `dotnet new webapi` pin below it (`10.0.10`), and adds that package before the `Regira.*` ones so adding sign-in later cannot downgrade it. Also corrects the severities: NU1603 warns, **NU1605 is an error** and fails every restore and build until cleared.
- `Regira.Entities` 6.1.3 — the `Supplier` slice in `entities.examples` used `[Route("[controller]")]`, which expands to the class-name stem: `SupplierController` served `/Supplier`, not the kebab-case plural `/suppliers` the paired SPA calls, so the one example marked copy-paste-safe 404'd every list request for that entity. It now spells the resource like the file's other controllers, and the guidance in `entities.instructions` → *Web endpoints* and `entities.setup` → *API route prefix* drops the token. `entities.setup` also shows `UseCentralRoutePrefix`'s call site (`AddControllers(o => …)`, since it extends `MvcOptions`).
- `Regira.Setup` 6.1.3 — `project.setup`'s *Key auth model types* listed the types under the **package** name `Regira.Security.Authentication`, a prefix of but not equal to any real namespace, so following it produced CS0234; the five namespaces now ship as copyable `using` lines pointing at `security.instructions` → *Namespace Quick Reference*. The NU1605 note gains the `dotnet new webapi` interaction and its recovery.
- `Regira.Security.Authentication.Web` 6.1.3 — the card's version-floor bullet adds the `Microsoft.AspNetCore.OpenApi` **10.0.11** floor beside the existing `Microsoft.OpenApi` one, since the template pin below it is what breaks the first authenticated build.
- `Regira.Office.Barcodes.ZXing`, `Regira.Entities.Mapping.Mapster`, `Regira.Office.Excel.MiniExcel`, `Regira.Globalization.LibPhoneNumber`, `Regira.IO.Storage.Azure`, `Regira.Office.PDF.Puppeteer` 6.1.3 — dependency moves only, no change to the Regira API surface: `ZXing.Net.Bindings.SkiaSharp` 0.16.22 → 0.16.23, `Mapster.DependencyInjection` 10.0.11 → 10.0.12, `MiniExcel` 1.45.0 → 1.46.0, `libphonenumber-csharp` 9.0.36 → 9.0.37, `Azure.Storage.Blobs` 12.29.1 → 12.29.2, `PuppeteerSharp` 25.5.0 → 25.8.0.
