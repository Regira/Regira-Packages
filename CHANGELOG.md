# Changelog

Release summary for the Regira NuGet packages — newest first. Every change that ships in a package
adds one bullet under **Unreleased** in the same change (format: `` `PackageId` x.y.z — summary ``),
and leaves that package's `<Version>` higher than its last published version. At publish time the
Unreleased block becomes a dated release heading.

## 6.1.2 — 2026-08-16

- All guide-shipping packages — the build-time guide extraction is gated **per file** instead of on one already-extracted sentinel, so a guide added by a package upgrade now reaches existing solutions (previously only brand-new solutions got new files, and `entities.blueprints.md`/`entities.card.md` were in no Copy list at all); the file set is now the packed `ai\*.md` glob, so newly packed guides extract without a targets edit; files with a destination of their own (`Regira.Setup`'s `copilot-instructions.md`, `CLAUDE.md`) are excluded and keep it. Files the consumer already has are never overwritten.
- All Apache-2.0 packages — the packed copyright drops "All rights reserved" (contradicted the Apache-2.0 grant beside it on nuget.org), and the repository `NOTICE` file is packed per Apache-2.0 §4(d); commercial packages keep the reserved-rights copyright and ship no NOTICE.
- All packages — version aligned at 6.1.2 for a whole-family publish, with dependency moves: `Microsoft.EntityFrameworkCore` (and `.Relational`) 9.0.18 → 9.0.19 and 10.0.10 → 10.0.11, the `Microsoft.Extensions.*` family, `Microsoft.AspNetCore.OpenApi`, `System.Runtime.Caching`, `System.Text.Json`, `System.Text.Encodings.Web`, `System.Drawing.Common`, `System.Formats.Asn1` and `System.Security.Cryptography.Xml` 10.0.10 → 10.0.11, `Microsoft.AspNetCore.Authentication.JwtBearer` and `.OpenIdConnect` 8.0.28 → 8.0.30 and 10.0.10 → 10.0.11, `MongoDB.Driver` 3.10.0 → 3.11.0, `MySqlConnector` 2.6.1 → 2.6.2, `SkiaSharp` 4.151.0 → 4.151.1, `Microsoft.Playwright` 1.61.0 → 1.62.0, `PuppeteerSharp` 25.4.0 → 25.5.0.
- `Regira.IO.Storage.SSH` 6.1.2 — `SSH.NET` 2025.1.0 → **2026.0.0**, a major-version move of the transitive dependency; the Regira API surface is unchanged, but a consumer pinning `SSH.NET` inherits the major on this patch update. Compile-verified only: the SSH storage tests need a reachable SSH server and skip without one.
- `Regira.Web` 6.1.2 — the `File(INamedFile)` download helper no longer writes `Content-Disposition`, `Access-Control-Expose-Headers` and `X-Content-Type-Options` before the null-stream check: a missing blob now returns a clean 404 instead of one advertising `attachment; filename="…"`.
- `Regira.Office.PDF.Spire` 6.1.2 — `Merge` (both overloads), `Split` and `GetText` now dispose every `PdfDocument` they open (in the stream merge the source documents stay open until the merged save, since inserted pages draw from them); each call previously leaked Spire native handles.
- `Regira.Entities.DependencyInjection` 6.1.2 — the attachments input-DTO startup check now requires the `Attachments` property's element type to be a materializable class: `ICollection<int>? Attachments` used to satisfy the name-and-IEnumerable probe while the convention map still dropped every attachment — the exact silent failure the check exists to catch.
- `Regira.Entities.DependencyInjection` 6.1.2 — the attachments input-DTO startup check now reads the **last** mapping registered for an entity, matching how DI resolves it. Re-registering `UseMapping` left the check validating a superseded DTO: it either warned about a DTO no longer in use, or passed while the effective one silently dropped attachments through the parent.
- `Regira.Common` 6.1.2 — `MemoryFileExtensions.GetStream()` no longer leaves the backing stream at EOF: it restored neither the source position nor the copy's, so a second `GetStream()` on the same file handed a sequential reader zero bytes (an empty attachment download over HTTP, with a correct `Content-Length`).
- `Regira.IO.Storage` 6.1.2 — `ZipBuilder.Build()` disposes the `ZipArchive` before materializing the result: the archive only writes its contents on Dispose, which ran after `ToMemoryFile` had already captured `Length`, so a freshly built zip reported `Length` 0; both branches now also hand the zip stream over rewound instead of parked at EOF.
- `Regira.IO.Storage` 6.1.2 — `ZipUtility.ToBinaryFile(ZipArchiveEntry)` rewinds the entry copy before storing it, so unzipped files no longer carry a `Stream` parked at EOF; consumers reading `file.Stream` directly (e.g. the GDI/SkiaSharp image decoders) got zero bytes, while `GetStream()`/`GetBytes()` masked it by rewinding internally.
- `Regira.Office.Excel.ClosedXML` 6.1.2 — `Create` rewinds the workbook stream before wrapping it in the returned file; it was left at EOF, so anything reading the returned `Stream` sequentially (e.g. `FileStreamResult`) got zero bytes while `Length` advertised the full size.
- `Regira.Office.Excel.MiniExcel` 6.1.2 — both `Create` overloads (untyped and `ExcelManager<T>`) rewind the workbook stream before wrapping it in the returned file; it was left at EOF, so anything reading the returned `Stream` sequentially got zero bytes while `Length` advertised the full size.
- `Regira.Office.Excel.NpoiMapper` 6.1.2 — both `Create` overloads (untyped and `ExcelManager<T>`) rewind the workbook stream before wrapping it in the returned file; it was left at EOF, so anything reading the returned `Stream` sequentially got zero bytes while `Length` advertised the full size.
- `Regira.DAL.MySQL.MySqlBackup` 6.1.2 — `Backup()` rewinds the export stream before wrapping it in the returned file; it was left at EOF, so anything reading the returned `Stream` sequentially got zero bytes while `Length` advertised the full size.
- `Regira.Entities` 6.1.2 — packed guides: worked *Role-gated write authorization filter* recipe (allow-list keyed on the controller, with the `POST search`/`POST list` read overloads and the separate attachment controller called out); the response-shape section now carries populated JSON for the search/save/400 envelopes and the attachment link DTO, whose file metadata nests under `attachment`; the *Feature recipes* index now lists every recipe in the patterns guide; EF translation hazards extended with method calls in projections and provider-specific `EF.Functions`; one `EntityAttachment` subclass per owner stated explicitly; version guidance changed from a `6.0.0` pin to a major-6 constraint resolved at add time.
- `Regira.Entities` 6.1.2 — packed guides: new owner-agnostic **Contact data & addresses** blueprint (child contracts + per-owner subclasses on any entity, folded into the owner's `Q`; the Stakeholders blueprint now builds on it) and a *When you don't need the full party model* decision guide (child collections on an existing entity → flat `Contact` table → full TPH party); `how_to` key `addresses`, with the address/contact aliases moved off `stakeholders`.
- `Regira.Entities` 6.1.2 — packed guides: a correlated `Any(...)` over a dependent carrying a **two-level** query filter needs SQL `APPLY` and fails on SQLite, so Step 11's filter recommendation now bounds the depth and the hazard list carries the uncorrelated rewrite; the primer-vs-prepper choice moved into both recipes that prescribe a primer, instead of only living in Step 9; §Error Handling now names which write surfaces catch `EntityInputException` rather than saying "controllers"; `FilterIsActiveOn` documented — the guides previously asserted no built-in helper consumed `IHasStartEndDate`.
- `Regira.Office` 6.1.2 — new packed guide `office.namespaces` (abstraction / model / provider namespace per module, the `BarcodeFormat`-vs-ZXing alias, and the `Regira.Common` file types every service returns); the PDF backend table gains a **runtime footprint** column — first-use browser downloads for the Chromium backends, `net*-windows` targets, and the `System.Drawing.Common` constraint.
- `Regira.IO.Storage` 6.1.2 — new packed guide `io.storage.namespaces`, including which file abstractions come from `Regira.Common` rather than a storage package.
- `Regira.Entities` 6.1.2 — packed guides: the two Regira `dotnet add package` commands drop `--version "6.*"` — the CLI writes a floating range through to the csproj verbatim instead of resolving a pin, the non-reproducible-restore case the surrounding table exists to prevent; the family-version note is scoped to directly-referenced packages; the deprecated AutoMapper alternative now names its NU1903 restore advisory.
- `Regira.Setup` 6.1.2 — packed guides: *Standard hosted API with auth* added to the template-selection tables (`BasicApi` plus `SelfHostingApiWithAuth`'s auth registrations), the shape an authenticated Entities API actually takes.
- `Regira.Web` 6.1.2 — packed guide: `UseCentralRoutePrefix` now names its package and namespace at the call site.

## 6.0.2 — 2026-08-08

- All packages — version aligned at 6.0.2 for a whole-family publish.
- `Regira.Entities.EFcore` 6.0.2 — a required relationship the change tracker refuses to sever is now reported as a constraint conflict (409) instead of an unhandled `InvalidOperationException`. EF resolves that case client-side, before the provider is reached, so it never arrived as the `DbUpdateException` the constraint path catches — a hierarchy that eager-loads its own children hit it on every parent delete. Both throw sites are covered (`Remove`, and `SaveChanges` under deferred cascade timing), including the `Attachment` principal removed by `EntityAttachmentWriteService`. Adds `InvalidOperationExceptionExtensions.IsSeveredRequiredRelationship`.
- `Regira.Entities` 6.0.2 — the packed `Order + OrderLine` example no longer rejects a partial update that omits the child collection: `Modify` validates only an explicitly emptied collection, matching the `Related()` contract the same snippet documents. Adds delete-behaviour guidance for a required self-referencing foreign key, and names the literal parameter in every MCP call example.
- `Regira.Setup` 6.0.3 — the packed setup guides name the literal parameter in every MCP call example.
- `Regira.TreeList` 6.0.2 — the packed examples name the literal parameter in every MCP call example.

## 6.0.1 — 2026-08-06

- All packages — version aligned at 6.0.1 for a whole-family publish.
- `Regira.Setup` 6.0.2 — the packed `copilot-instructions.md` no longer routes a "NuGet feed" setup concern to `shared.setup.md`; packages install from nuget.org with no feed configuration.
- `Regira.Office.PDF.SelectPdf` 6.0.1 — ships a `buildTransitive` targets file that copies SelectPdf's native `Select.Html.dep` into the consumer's build and publish output. NuGet does not flow the upstream package's `contentFiles` through a transitive reference, so every consumer built cleanly and then threw `Conversion failure. Could not find 'Select.Html.dep'` on the first conversion. Opt out with `RegiraSelectPdfCopyNativeDep=false`.
- `Regira.Office.OCR.Tesseract` 6.0.1 — ships a `buildTransitive` targets file that copies `tessdata/eng.traineddata` into the consumer's build and publish output, for the same reason. The trained data now packs once at a fixed `tessdata/` path instead of four times via the automatic `contentFiles` layout (7.5 MB → 1.9 MB), and `tessdata/readme.md` is no longer shipped to consumers. Opt out with `RegiraTesseractCopyTessData=false`.
- `Regira.Office` 6.0.1 — packed guides: results are read with `GetBytes()`, never `.Bytes`. `IMemoryFile` carries either bytes or a stream depending on the method (DocNET's `Split` returns bytes, its `Merge(IEnumerable<IMemoryFile>)` a stream), so `.Bytes` was null for half the API and produced a 200 with an empty body; the PDF, Word, mail, OCR and barcode examples used it.
- `Regira.IO.Storage` 6.0.1 — packed guide and README: `GetBytes()`/`GetStream()` are documented under `MemoryFileExtensions` (`Regira.IO.Extensions`, in `Regira.Common`) rather than under a `BinaryFileExtensions` heading, with the empty-body trap stated where `Save` is described.
- `Regira.Media` 6.0.1, `Regira.System` 6.0.1, `Regira.Web` 6.0.1 — packed guides use `GetBytes()` on `IMemoryFile` results, consistent with the rule above.
- `Regira.Entities` 6.0.1 — packed guides: the non-owned child aggregate recipe is a top-level pattern reachable from the relationship decision table; a dependent's archived query filter also hides its rows from the parent's aggregate recompute (`IgnoreQueryFilters()`, scoped by the parent FK); after-mappers run for the read root only, so a field needed on a nested DTO belongs on the entity; an earlier seed wave is re-read detached, not through `Details()`; seed checks cover state ratios, not only `count: 0` invariants; report endpoints project a `GroupBy` into an anonymous type and prefer a join over a correlated `SelectMany`; the shared `Attachment` base costs no licence slot; `OrderOrThenBy` chains within one `SortBy` arm.
