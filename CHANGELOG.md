# Changelog

Release summary for the Regira NuGet packages — newest first. Every change that ships in a package
adds one bullet under **Unreleased** in the same change (format: `` `PackageId` x.y.z — summary ``),
and leaves that package's `<Version>` higher than its last published version. At publish time the
Unreleased block becomes a dated release heading.

## 6.3.0 — 2026-09-16

- `Regira.Entities` 6.3.0 — `[VersionStamp]` gains `Required`: `[VersionStamp(Required = true)]` refuses an update whose client left the stamp out, where an absent stamp otherwise writes unchecked — for a client that must always prove what it read. It serves on the implementing `ConcurrencyToken` property of `IHasConcurrencyToken` too, which is a stamp already, for that purpose alone. `entities.patterns` (the DTO rules and the *what each write is checked against* table), `entities.card` and `entities.namespaces` say so, and the developer docs in `built-in-features`.
- `Regira.Entities.EFcore` 6.3.0 — an update whose client left a `[VersionStamp(Required = true)]` token out is refused with `EntityInputException<TEntity>` — HTTP 400 through the existing mapping, the property name as the field, the incoming entity as `Item` — before anything is attached, so the change tracker is as the caller left it. Owned children synced by `Related()` and attachment join rows are held to the same rule. An insert is never refused, and a `PATCH` without the token in its body still carries the merge base's. A token nothing has yet decided the kind of is kept in a table keyed weakly on the context; its lifecycle is now stated where it lives, and a pooled context that returns to the pool with an unsaved update drops that entry on its next save without writing it. The write path and the delete-cycle breaker share one notion of a store-generated token, so a computed-column token (`ValueGeneratedOnUpdateSometimes`) is refreshed after the reference drop as a rowversion is, and the `DELETE` that follows carries its current value.
- `Regira.Entities.DependencyInjection` 6.3.0 — startup validation reports an error, not a warning, when the input DTO has no property for a token declared `[VersionStamp(Required = true)]`: the write path refuses every update without it, so every `PUT` and `PATCH` through the entity controller would answer 400.
- All packages — version aligned at 6.3.0 for a whole-family publish. Twenty-one packages carry a change of their own, all below, and `Regira.DAL.SqlServer`, `Regira.Office.Word.Syncfusion`, `Regira.Office.Word.Aspose` and `Regira.Office.Word.Gotenberg` are new to the family. The minor is what the family's own rule asks for here: `Regira.Entities` gains a type a consumer has to go and adopt (`IHasConcurrencyToken`) and the SQL Server backend is a package that did not exist, so the aligned number follows the largest step rather than the smallest. Nothing is published outside it, and no upstream dependency moved this cycle — the references that appear are new ones, each named under its own package. The remaining packages are republished unchanged so the family shares one version.
- `Regira.Entities` 6.3.0 — guide-only, closing the gaps two MCP-only application builds ran into. *Response Types* states that a null value is **absent** from the payload rather than `null` (`ConfigureDefaultJsonOptions` sets `WhenWritingNull`), and the two samples that carried `"lastModified": null` no longer contradict it — a client asserting `=== null` after an action that clears a foreign key fails against a correct API. *Security & Authorization* names the two create-side holes a scoping filter leaves: an attachment upload takes its owner id from the route and runs no query, so no global filter sees it and any authenticated caller can attach a file to a row it cannot read; and a read scope deliberately wider than the write scope (a manager seeing their reports' rows) silently grants `PATCH`/`DELETE` on them, because the write endpoints' existence checks run that same filter — both closed with a prepper. The *Domain actions* recipe answers in the envelope the generated endpoints use (`this.DetailsResult(item)`) instead of a bare `Ok(item)`, so a client reads `data.item` on every route. The `IQKeywordHelper` guidance extends to hand-written text filters: `EF.Functions.Like`, because EF translates `string.Contains` to SQLite's case-sensitive `instr()` and `?q=emma` then silently finds nothing while `?q=Emma` works.

- `Regira.Office.Word.Syncfusion` 6.3.0 — new package: `WordService` implements the full `IWordService` on Syncfusion DocIO, the second backend after Word.Spire to cover all seven methods. It exists because FreeSpire.Doc caps a free-edition document at 500 paragraphs or 25 tables, which real documents hit; DocIO has no size cap. It does need a commercial licence key — Document SDK is priced per developer per year with a minimum team size ([Syncfusion pricing](https://www.syncfusion.com/sales/products)), and whether their Community Licence extends to it is not something their own pages agree on, so the guides tell a consumer to confirm with Syncfusion rather than assume a free tier. The template contract is Word.Spire's, reproduced: `{{ key }}` substitution with `\n` becoming a soft line break, `html_`-prefixed keys injecting HTML into the owning paragraph, bookmark-name substitution, collection tables located by Alt-Text Title with row 1 cloned per item and a `{{ row_number }}` key, image replacement matched on Title or Alternative Text with the original width and height restored, nested-document insertion, and per-section headers and footers. Nested insertion clones child entities into the placeholder's container rather than calling DocIO's document-replace overload, carrying across the reasoning that made Word.Spire avoid its vendor's equivalent. A template that includes itself — as a nested document, a header or a footer — fails once documents nest 100 levels deep; the depth is counted per call, so a long-lived or shared instance never runs out. A collection whose table the template lacks leaves the other collections applied, a `null` parameter value writes empty text, an `html_` key the template lacks is ignored like any other, and an `Even` header or footer switches the document to separate odd and even pages so that it renders. Where adding a `FirstPage` or `Even` version switches those pages to stories of their own, the story given no such version — a footer with page numbers under an even header, say — gets its default content there, instead of vanishing from those pages. Page settings honour every `PageSize`, A0 to A10, computed from millimetres where DocIO's own list stops, and a picture given `Justify` keeps its default position rather than throwing. The documents a merge and the headers and footers are built from are disposed as soon as their content is copied, and a document whose build fails is disposed too. Parameter keys are matched literally, so `Total (EUR)` is replaced and `x[1` no longer fails the call; a `DocumentBuilder` with nothing loaded builds on a document with one section; and a page without text width scales nothing instead of dividing by zero. **Two formats are out of reach and throw `NotSupportedException` rather than failing obscurely:** ODT cannot be *loaded* (saving to ODT works), detected from the template's own bytes so the caller gets that sentence instead of DocIO's *not a valid DOCX* message, and EPUB export is unavailable on .NET Core. `Png`/`Jpeg` throw too, pointing at `ToImages`. `Convert` reports the content type of the format it actually produced — Word.Spire tags every result as Word — and `ToImages` reads the encoding back from the rendered bytes rather than assuming one. The licence key goes to the constructor (`new WordService(new SyncfusionWordConfig { LicenseKey = … })`), because DocIO must be handed it before the first document is touched or it silently stamps trial text into the output; like the rest of the Office family, the package has no DI extension and depends on nothing but DocIO — a container registers the config and the service under the interfaces it injects. The key also resolves from `SYNCFUSION_LICENSE_KEY`, and is registered once per process — DocIO concatenates keys handed to it repeatedly. PDF conversion and `ToImages` go through `Syncfusion.DocIORenderer`, which renders with SkiaSharp 3.119.1 and HarfBuzzSharp 8.3.1.2; Linux consumers add `SkiaSharp.NativeAssets.Linux` and `HarfBuzzSharp.NativeAssets.Linux` at the versions their application resolves. The package does **not** reference `Regira.Drawing.SkiaSharp`, which pins SkiaSharp 4.x against the renderer's 3.x — `RenderAsImages` already returns encoded images, so nothing needs decoding. `EnforceEvenAmountOfPages` costs a full PDF render, because DocIO exposes no page count on the document model. Tests: `tests/Office.Word.testing/SyncfusionTests.cs`, which runs unlicensed apart from one test that needs `SYNCFUSION_LICENSE_KEY`. `License_Key_Removes_The_Trial_Banner` is the one that answers whether a given key licenses DocIO: the trial banner is ordinary body text prepended to the document, so every other assertion in the fixture passes against a watermarked file, and only a test asserting its absence catches a key that is missing, wrong, or does not cover the Word library.

- `Regira.Office.Word.Spire` 6.3.0 — **bug fixes** in template processing. The guard against a template that includes itself counted every nested insert over the service instance's lifetime, in a field shared by every thread: a long-lived `WordService` — a singleton, a field, a `DocumentBuilder` — threw *"Maximum insertable documents reached"* for good once 100 nested inserts had accumulated across its calls. It now bounds the nesting depth of each call (100 levels), per flow of execution, and also catches a template that includes itself through a header or a footer, which recursed until the stack overflowed; the exception is an `InvalidOperationException`. A `CollectionParameters` entry whose table the template lacks ended the loop, silently skipping every collection after it; it is now skipped alone. A parameter key went into a regular expression as written, so `Total (EUR)` was left in the document and `x[1` threw `RegexParseException` out of `Create`; keys — global, collection-column and nested-document — are matched literally now. A `null` parameter value threw `NullReferenceException` and now writes empty text — in collection rows too — and an `html_` key the template lacks threw the same and is now ignored, like any other unused key. An `Even` header or footer was written but never rendered, because the document was never told to tell odd and even pages apart; it is now. And a `FirstPage` header or footer gave the first page stories of its own, so the other story — the footer under a first-page header, the header above a first-page footer — disappeared from page 1; where adding the input switches first-page or even-page stories on, the story given no such version now repeats its default content there, which also keeps page numbers on even pages under an `Even` header.
- `Regira.Office.Word.Mini` 6.3.0 — **bug fix:** a template tag written with spaces inside the braces, or split by Word over several runs, is replaced. MiniWord matches a tag only when the text between the braces is the key itself and the whole tag sits in one run, so `{{ title }}` never matched the key `title`, `{{ Items.Name }}` never filled a collection row, and a tag Word had split while it was edited was left in the document as literal text — while the other backends match `{{ *key *}}` across runs. The same `WordTemplateInput` therefore produced different documents depending on the backend, and silently: nothing threw, the tag simply survived into the output. `Create` now rewrites the template's tags through the Open XML SDK it already depends on before MiniWord reads it — spaces just inside the braces dropped, a split tag moved into the run it starts in, in the body, headers and footers, each paragraph read without the text boxes it contains — so `{{title}}`, `{{ title }}`, `{{ Items.Name }}` and an edited tag all match. A key the caller spelled with spaces still finds its tag, and never displaces a key supplied without them. Global parameters now render identically on every creator; collections and images keep MiniWord's own template syntax — `{{Items.Name}}` rows, `{{logo}}` tags — which the guides now spell out.
- `Regira.Office.Word.Mini` 6.3.0 — `WordCreator` is renamed **`WordService`**, now that it does more than create; `WordCreator` remains as an `[Obsolete]` subclass so existing code keeps compiling, the way `IWordManager` shadows `IWordService`. It implements `IWordTextExtractor` and `IWordImageExtractor` alongside `IWordCreator`, so the MIT backend now covers the model-side half of `IWordService` and a consumer that only reads documents needs no vendor licence and hits no document size cap. Both read the *rendered* document, matching Word.Spire, and go through the Open XML SDK that MiniWord already depends on — no new package enters the graph, though it is now a direct reference since the code uses it. `GetText` walks paragraphs (body, then headers, then footers) emitting tabs and line breaks, rather than concatenating runs into one unseparated string; `GetImages` resolves each DrawingML blip to its image part for the bytes and content type, takes the name from the Alt-Text Title (then Description, then the object name) the way Word.Spire matches images, and the size from the drawing extent, then sweeps any image part no drawing referenced (a legacy VML shape) so nothing is silently dropped. **Behaviour change:** `Create` throws `NotSupportedException` for `DocumentParameters`, `Headers`, `Footers` and any non-default `InputOptions` instead of ignoring them — MiniWord has no API for any of them, so a caller passing headers got a document quietly missing them; a default-initialised `WordTemplateInput` is unaffected. A key used in more than one of `GlobalParameters`, `Images` and `CollectionParameters` now throws `ArgumentException` naming the key, where `ToDictionary` raised a bare *an item with the same key* out of the dictionary build. Three fixes on the way through: the result carries `ContentTypes.DOCX` (it carried none, so the same call returned a different shape depending on the backend) and its stream is rewound (`ToBinaryFile` captured it at its end, so a consumer reading `.Stream` rather than `GetStream()` read nothing); a `WordImage` with no `Size` no longer writes `0` into `MiniWordPicture`, whose own default is 400x400, so an image without explicit dimensions rendered at zero width and height; and the picture's `Extension` is derived from the file name, content type or byte signature, without which MiniWord picks the wrong image part type and Word refuses to render the picture. The package multi-targets `net8.0;net10.0` like the rest of the family — MiniWord itself targets `netstandard2.0`, so the `net10.0`-only floor was never its constraint. First tests for the package: `tests/Office.Word.testing/MiniTests.cs`.

- `Regira.Office.Word.Gotenberg` 6.3.0 — new package: `WordService` converts Word documents to PDF and renders their pages as images through the LibreOffice route of a [Gotenberg](https://gotenberg.dev) server (MIT, Docker) — the route to `Convert` and `ToImages` without a vendor licence, since no free in-process .NET library has a Word layout engine. It implements `IWordConverter` and `IWordToImagesService` only, as Gotenberg has no document model. `Convert` produces PDF and throws `NotSupportedException` for every other format; a source may be a Word, OpenDocument, RTF, plain-text, HTML or EPUB document, uploaded under the extension its file name or, failing that, its content gives. The route has no page-size or margin fields, so `ConversionOptions.Settings` is written into the document's section properties before upload, with Word.Spire's table and picture scaling — which needs an OOXML source and honours every `PageSize`; a negative left or right margin, which the format cannot hold, becomes zero. Two collaborators come from the constructor or the container: an `IWordCreator` renders an input that carries template substitutions, which otherwise throws `NotSupportedException` — Word.Mini for global parameters, collections and images, a backend with a document model for headers, footers and nested documents — and an `IPdfToImageService` (PDF.DocNET, for example) rasterises the PDF for `ToImages`, since Gotenberg has no route that does. `AddGotenbergWord` registers both interfaces on one `HttpClient` (base URL, timeout, basic auth) named `ServiceCollectionExtensions.HttpClientName`, not after an interface: `AddOfficeClients` names its clients after theirs, so a shared `IWordConverter` client would have carried Gotenberg's basic-auth header to the Regira Office API, or the Office API's licence key to Gotenberg, depending on registration order. A 503 from the server's own `--api-timeout` is reported as such. The guides say what LibreOffice's layout means for page images and page counts: a font missing from the container is substituted, which moves line and page breaks.
- `Regira.Office.Word.Aspose` 6.3.0 — new package: `WordService` implements the full `IWordService` on Aspose.Words, a port of Word.Spire's template contract — `{{ key }}` substitution with line breaks, `html_` parameters, bookmarks, collection tables by Alt-Text Title with `{{ row_number }}`, image replacement by Title or Alternative Text keeping the placeholder's size, nested documents, and headers and footers — plus `DocumentBuilder`. It is the one backend that both loads ODT templates and writes EPUB, and `Convert` writes every document format (image output comes from `ToImages`). `Convert` reports the content type of the format it produced, and page settings honour every `PageSize`, A0 to A10, where Aspose's own paper-size list stops at A5, and a page without text width scales nothing instead of dividing by zero. Parameter values are inserted verbatim — Aspose's replace reads `&p`, `&l`, `&m` and `&b` as breaks even with a regular-expression pattern, so ampersands are escaped. The template processing matches Word.Spire's corrected behaviour: the self-inclusion guard bounds each call's nesting depth, headers and footers included; a missing collection table skips only that collection; a `null` value writes empty text; an `Even` header or footer switches on odd and even pages; and a story given no `FirstPage` or `Even` version repeats its default content on those pages. When none of the four resolves — `LicensePath = configuration["Aspose:LicensePath"]` with the key missing — constructing the service throws instead of producing watermarked, truncated documents with nothing in the logs; `AsposeWordConfig.AllowEvaluation` accepts evaluation output deliberately, and a process that already holds a licence needs neither. The same licence is recognised by where it comes from and read once, a licence Aspose rejects is no longer counted as the one applied, and a licence file that cannot be read is reported with the setting that named it. Evaluation mode replaces the document's own headers and footers with its banner. - `Regira.Entities.EFcore` 6.3.0 — **behaviour change:** `EntityPrimerContainerInterceptor` and `EntityNormalizerContainerInterceptor` run on a synchronous `SaveChanges()` too. Both overrode only `SavingChangesAsync`, which EF Core never calls for the synchronous save, so a seeder, a job or a context's own `SaveChanges` override skipped every primer and normalizer without a trace: `Remove` on an `IArchivable` entity hard-deleted the row, `Created`/`LastModified` went unstamped, custom primers (`AddPrimer`, `e.Prime(...)`) never ran and `[Normalized]` fields stayed empty. Regira's own write path saves asynchronously, which is why nothing caught it. The synchronous call runs the same primers and normalizers in the same order, and waits on them with the caller's `SynchronizationContext` removed — or, under a non-default `TaskScheduler`, from the default one — so a primer that awaits (the attachment primer's storage write, a lookup through the context) cannot deadlock a UI thread, a single-threaded async context or an exclusive scheduler; it holds the calling thread for that I/O, as the synchronous save already does for its own round trip. The primer and normalizer contracts are unchanged. A caller that compensated by calling `ApplyPrimers()` before a synchronous save, with the interceptor wired, now primes twice — drop the explicit call, as on the asynchronous path.
- `Regira.DAL.EFcore` 6.3.0 — `AutoTruncateDbContextInterceptor` truncates on a synchronous `SaveChanges()` too. It overrode only `SavingChangesAsync`, so a synchronous save sent over-long strings to the database unclipped — a truncation error on SQL Server, silently stored on SQLite.
- `Regira.DAL.EFcore` 6.3.0 — the attribute metadata cache every save reads is filled atomically. `EntityTypeExtensions.GetPropertyAttributes` held a `ConcurrentDictionary` through an `IDictionary` reference, which leaves only `ContainsKey` followed by `Add` to prime it: two requests reaching the same entity type for the first time both passed the check, and the one that lost the race was handed `ArgumentException: The key already existed in the dictionary` out of `SaveChanges` — through the auto-truncate interceptor, so nothing in the stack named a cache. Only concurrent *first* use can hit it, which is why a warm process never reproduced it. `GetOrAdd` replaces the check-then-act pair.
- `Regira.Entities` 6.3.0 — guide-only: `entities.instructions` §Step 9 states that primers, normalizers and auto-truncate run on `SaveChanges()` and `SaveChangesAsync()` alike, and what an awaiting primer costs a synchronous caller — its own awaits do not deadlock the caller, while it holds the calling thread for its I/O. The repository's `docs/` (`services`, `normalizing`, `built-in-features`) say the same, and `built-in-features` names the interceptor `AddAutoTruncateInterceptors()` actually adds — `AutoTruncateDbContextInterceptor`, not `AutoTruncatePrimer`.
- `Regira.Entities.EFcore` 6.3.0 — **behaviour change:** optimistic concurrency works through the entity write path. `Modify` reloads the stored row and copied it into the incoming entity's original values, so every concurrency token's original value was the database's own and `UPDATE … WHERE token = @original` compared the database with itself: a client editing a stale copy always won, and only a write landing between the reload and `SaveChanges` was caught — which is what made the check look alive. The token the client sent now becomes the original value of every **version stamp** — a token the server moves on the write: one the database generates on update (`[Timestamp]`/`IsRowVersion()`), `IHasConcurrencyToken.ConcurrencyToken`, a token carrying the new `[VersionStamp]`, or any other `[ConcurrencyCheck]`/`IsConcurrencyToken()` property a prepper or primer changes on the write — the last decided once the primers have run, on the interceptor path and on an explicit `ApplyPrimers()` alike, and only for that write, so a primer that reproduces the client's value (a content hash) needs the attribute for a stale write to be refused. It is read before the preppers run, so a `[ServerOwned]` restore cannot mask it, and the same holds for owned children synced by `Related()` and for attachment join rows. A version stamp the client leaves out (`null`, empty, or the property's sentinel) is not compared, and is not written over the stored one. A token nothing moves is a **data column** the client edits (`[ConcurrencyCheck] public string LastName`): its value is written as sent, a change or a clear, and it is compared with the stored row, so only a write racing the save is caught — making the client's new value the original would have refused every change and silently undone every clear. `SaveChanges` rethrows EF's `DbUpdateConcurrencyException` as `EntityConcurrencyException`, with EF's exception on `InnerException`: a direct caller catching `DbUpdateConcurrencyException` around `IEntityService.SaveChanges()` must catch the new type, which also covers an `UPDATE`/`DELETE` that matched no row because another writer removed it, token or not. An app that already declares a token and carries it on its input DTO starts receiving conflicts for stale writes that used to overwrite silently. For the portable opt-in, `ConcurrencyTokenConvention` declares `IHasConcurrencyToken.ConcurrencyToken` a concurrency token — also where a mapped base type that does not carry the marker declares the property — from the context's options — wired by `UseDefaults()`, or by the new `AddConcurrencyTokenConvention()` on a hand-built context, and applied at model finalization so an explicit `.IsConcurrencyToken(false)` still wins — and the new `HasConcurrencyTokenDbPrimer` mints a new value on every insert (unless one is given) and every update, a soft delete and a raw-`DbContext` write included: a token nothing re-mints lets two clients holding the same value both pass. A hard delete issued from a stub survives the marker. `Remove(new Order { Id = id })` carries no token, so EF compared the stored row against `Guid.Empty`, matched nothing, and the delete failed as a conflict every time it was retried — opting an entity into `IHasConcurrencyToken` would have made deleting it by key impossible. `HasConcurrencyTokenDbPrimer` now reads the stored token for a delete that claims none and deletes against that: an absent token is the absence of a claim, not a claim of emptiness, while a caller that does hold one keeps its check and a stale value is still refused. `RelatedAttachmentsPrepper` had the same stub in its cascade and now reads the attachment first when the attachment type carries the marker, keeping the saved round trip for types that do not.
- `Regira.Entities.Web` 6.3.0 — **behaviour change:** `EntityConcurrencyException` answers **409 Conflict** instead of 500, with the new `EntityConcurrencyProblem` body titled *"Concurrency conflict"* — the constraint 409 is titled *"Conflict"* — so a client can tell "reload and try again" from "fix the input". Mapped by `EntityExceptionFilter`, by the `ControllerExtensions.Save`/`Delete` helpers (so `PUT`, `PATCH` and `DELETE`), and by `[EntityConstraintConflict]` on the attachment controller bases, which now maps both conflicts the write pipeline raises. `entities.web.namespaces` lists the problem types.
- `Regira.Entities.DependencyInjection` 6.3.0 — `UseDefaults()` wires the concurrency-token convention (the new `DbContextWiring.ConcurrencyTokens`, part of `DbContextWiring.All`) and `AddDefaultPrimers()` registers `HasConcurrencyTokenDbPrimer` after `ArchivablePrimer`, so implementing `IHasConcurrencyToken` is the whole opt-in; a setup counting its registered primers sees one more. Startup validation reports a concurrency token that is never checked, never moves or cannot make the round trip. An error when an `IHasConcurrencyToken` entity's context never got the wiring (a non-generic `UseEntities()`, or `WireDbContext(...)` without the flag); an explicit `.IsConcurrencyToken(false)` on a wired context is a deliberate opt-out and is left alone. EF Core refuses the whole save with *a circular dependency was detected in the data to be saved*, so `IEntityService.Remove` + `SaveChanges`, and therefore the generated `DELETE` route, answers 500 for every owner whose children are loaded. Nothing inside `SaveChanges` can resolve it: primers and preppers do run for deleted entries, but EF orders the deletes from the **original** foreign-key values, so what they set is never read — and faking the original value only moves the failure to the database, which still holds the reference while the row it points at is deleted. The extensions are called **from the context's own `SaveChanges`/`SaveChangesAsync` overrides** (both of them) and drop the optional side of the pair with a direct `UPDATE` — guarded by the row's key and concurrency tokens like EF's own, so another writer's change surfaces as `DbUpdateConcurrencyException` rather than being overwritten — before the one save that carries the `DELETE`s, in one transaction and through the context's execution strategy — a transaction the caller already owns, its own or an ambient `TransactionScope`, is joined rather than nested, which is what keeps the shape working under `EnableRetryOnFailure()`: EF's own recipe for combining the two puts the save inside a strategy the caller owns, and a second transaction in there is a second unit of work the retry cannot replay. The strategy itself is not the hazard: nested inside the caller's it is suspended, and a bare `BeginTransaction()` with no strategy around it is refused by EF's own `SaveChanges`, with or without the extension. The ambient case is the one that cannot be inferred — `Database.CurrentTransaction` is null inside a `TransactionScope`, so the extension checks `Transaction.Current` too, where beginning a transaction on the enlisted connection would throw. `acceptAllChangesOnSuccess` goes to the extension and reaches the delegate as a parameter, unchanged: the real save runs exactly once, with or without a cycle, and nothing is accepted before it returns — so a save the database rejects leaves the change tracker holding every pending change, the tracker's view of the dropped reference is put back, and the retry EF's strategy or the caller makes drops it again and completes the whole unit of work; `SaveChanges(false)` + `AcceptAllChanges()` behaves exactly as without the extension. The value returned is the save's own count, each row once — the `UPDATE` is not counted. A save with no such pair opens no transaction. Direct pairs only: a longer ring (`A → B → C → A`) is left to EF's own exception rather than resolved by guessing which link is incidental.
