## Recurring shapes

Lessons that keep coming back; the entries below lean on them instead of restating them.

- **A check that skips is indistinguishable from one that passes.** A filter that never runs, a validator that cannot resolve what it checks, an interceptor hook that never fires and a licence check against evaluation output all stay green. Prove the check executes: flip its predicate (`Where(_ => false)`) and watch results change, or keep a sibling test in which it must fail. *(2026-07-20)*
- **Verify a report against current source and the shipped artifact before acting.** Many evaluation findings are already fixed, never real, or a consumer's own trap: a sample's "confirmed framework quirk" (count right, each page one row short) was the documented archived-filter join, written up before the app added the mirror filter that fixed it. A *count right, items short* pair is that join until proven otherwise. Re-fixing a non-bug is a spurious change to a published package. *(2026-07-09, 2026-09-04)*
- **Measure framework behaviour before building on it, and resolve every DI shape a guide recommends in a test before writing it down.** Premises from memory ("it throws") and untested guide recipes have both shipped wrong. *(2026-09-30)*

## Guides and docs

- **The `ai/*.md` guides are the MCP's source of truth — keep them in lockstep with the public API.** The knowledge builder copies each `ai/` folder near-verbatim (it rewrites relative `.md` links and drops `<!-- no-compile -->` markers), so a stale guide makes the MCP confidently return non-compiling code. Edit the sources, never the generated output. When adding or renaming a public API, especially a DI extension, update the examples, instructions, namespaces and signatures files and the `docs/` mirror in the same change. *(2026-06-19)*
- **The source map is a reflected surface, not intent.** A package with a source map and no signatures guide gets a synthesized `api.generated` section: types, no prose. The scanner reads declared members only, so an interface that only inherits shows an empty member list, and its guide is the only contract an agent sees. *(2026-06-17, 2026-06-19)*
- **Keep consumer instructions Regira-scoped.** The agent is already a .NET/Vue expert; the bootstrap's "You are the .NET expert" section names the few cross-cutting traps and stops. General NuGet/EF/Vite/CVE advice does not belong in the guides. Only a genuinely Regira-scoped gap earns a note, such as an advisory a Regira default drags in or a peer dependency missing from a Regira scaffold. *(2026-07-01)*
- **Guides ship inside the packages, so a wrong snippet is a shipped defect.** Hub csprojs pack their `ai/` files and the `build/*.targets` copy them into every consumer's `.regira/instructions/`, so the packed list is the blast radius. When an API changes or a rule is found, sweep the **examples** files across the whole family, not only the instructions file that surfaced it (`.Bytes!` had shipped in nine families' guides). Check a claim against every implementation before writing "every backend does X". `tools/GuideVerifier` compiles snippets per group in `projects.json`, so a new family needs a group there. *(2026-07-30, 2026-08-05)*
- **A package id that is a prefix of the real namespaces reads as a namespace.** A types list headed `Regira.Security.Authentication` makes `using Regira.Security.Authentication;` compose in the reader's head, and it fails as CS0234 because the types live in sub-namespaces. Any guide that lists types under a package name needs the `using` lines at the point of use. *(2026-08-17)*
- **A `dotnet new` template's pin can sit below a Regira package's floor.** The `webapi` template pins `Microsoft.AspNetCore.OpenApi` at its own SDK band's patch, and `Regira.Security.Authentication.Web` references a later one, so adding it fails restore with NU1605. That code is an error, while NU1603 is only a warning. `dotnet add package` still writes the reference while the downgrade is live, so `dotnet add package Microsoft.AspNetCore.OpenApi` is the clean recovery and no hand-editing is needed. Only the security web package carries that floor. *(2026-08-17)*
- **Document the invariant, not the tree.** A layout guide that shows one folder tree is wrong the day an app outgrows it. `entities.setup` §Project Structure states what every layout shares first: the per-entity file set, so moving between layouts is a move by suffix. It then gives the triggers for the layered solution. Everything else, `/new-entity` included, points there. *(2026-09-06)*

## Entities and EF Core

- **License slots count distinct entity types per tier, not registration calls.** Each tier is de-duplicated and the shared attachment base (`IAttachment`) is skipped. Attachments on an entity therefore cost one simple slot, for the per-owner join from `HasAttachments`, and the `Attachment` base from `WithAttachments` is free. Guides quoting the cost must say "join = 1, base free". *(2026-06-20)*
- **`GET /search` (single, counted) is on every controller base.** Only the batch `POST /list` and `POST /search` are complex-only. Keep the web namespaces guide, the back-end instructions and the front-end guide in lockstep on it. *(2026-07-01)*
- **Paging: `PagingInfo.PageSize` is nullable, so the HTTP boundary tells an omitted size from `0`.** An omitted size gets `DefaultPageSize`, `<= 0` gets `MaxPageSize`, and a positive size is clamped to `MaxPageSize`. `UseDefaults()` sets 10 and 100. One helper in the `Entities.Web` controllers applies this. The DAL applies the value as-is (null or `<= 0` returns everything), so a direct `IEntityService` call bypasses both knobs on purpose. *(2026-07-01)*
- **A type's scope set must include the type itself, because `GetBaseTypes` returns only what it derives from.** A global filter scoped to a concrete entity never ran, since the applicability test used `GetBaseTypes(typeof(TEntity))` alone. Interface-scoped filters worked, so every test passed over the hole. Applicability now lives in one place, shared by the runtime and the startup validator. *(2026-07-20)*
- **Run startup diagnostics inside `provider.CreateScope()`.** Registration validators resolved from the root provider could not build any row-security filter, because each needs the caller's scoped identity. The check meant to catch an inert security filter therefore downgraded itself to "could not resolve". *(2026-07-27)*
- **Model configuration can be wired from DI.** An `IDbContextOptionsExtension` registers an `IConventionSetPlugin` with an `IModelFinalizingConvention`, which writes the archived query filter from the context's options after everything `OnModelCreating` configured. That puts `"Regira:Archived"` after the app's own filters without a consumer call. Prefer this over replacing `IModelCustomizer`, which forces a choice between `ModelCustomizer` and `RelationalModelCustomizer`. The limit is DI reach: a hand-constructed `new AppDbContext(options)` (tests, design-time factories) skips it. Ship the `DbContextOptionsBuilder` extension beside the wiring, with a `DbContextOptionsBuilder<TContext>` overload so the chain keeps its type. *(2026-08-03)*
- **`[ServerOwned]` is enforced by a prepper, not a primer.** A primer runs in every `SaveChanges`, so a blanket restore would revert legitimate raw-`DbContext` writes. It would also swallow every soft delete, because the archivable primer turns a delete into `Modified`. `EntityWriteService.Modify` already hands the stored row to `Prepare(modified, original)`, which makes the prepper's restore authoritative and free. Skip what cannot be protected (navigations, `IsArchived`), and have the startup validator report the same set. Owned children registered through `Related()` are written by the parent's prepper chain, so they need it passed in as a nested prepper. *(2026-08-27)*
- **A delete cycle has no seam inside `SaveChanges`.** An entity with a foreign key to its own child makes the pair reference each other, and EF refuses the save as a circular dependency. Nulling the key in a primer is ignored, because EF orders deletes from the **original** values. Nulling the original drops the edge, but the database then rejects the delete. Two statements are needed, so `SaveChangesBreakingDeleteCycles` wraps `SaveChanges` in the consumer's override rather than in an interceptor. The helper:
  - calls `ChangeTracker.CascadeChanges()` first, for `OnSaveChanges` timing;
  - nulls the **original** value after its direct `UPDATE`;
  - checks the model and `Database.IsRelational()` before touching the tracker, because `Entries()` runs `DetectChanges` and the in-memory provider needs no help;
  - matches principals through a key dictionary rather than a nested scan.

  *(2026-08-30, revised 2026-09-16)*
- **A wrapper owns the arguments its callee's contract depends on.** `SaveChangesBreakingDeleteCycles` skips its own `BeginTransaction` under a caller's transaction. It checks `Transaction.Current` as well as `Database.CurrentTransaction`, which never sees an ambient `TransactionScope`. SQLite cannot enlist, so that path is inferred from EF's source, not observed. `acceptAllChangesOnSuccess` must be the helper's parameter, passed into the delegate: phase one forces `true`, or its unaccepted originals raise the cycle again in phase two. Before blaming a wrapper, check what the plain call does; the execution strategy was blamed first and was innocent. *(2026-08-31)*
- **Reloading the stored row into `OriginalValues` makes a concurrency token vacuous.** EF builds `WHERE token = @original`, so the database was compared with itself and a stale client always won. The client's token has to become the original, and it must be read *before* the preppers run, because `[ServerOwned]` restores from the stored row. The three attach sites share one helper, which the startup validator uses too. An absent token is neither compared nor written. An initializer on the token makes every freshly mapped entity look stale, so every PUT answers 409. *(2026-09-11)*
- **A concurrency token is a version stamp only when the server moves it.** For `[Timestamp]`, `IHasConcurrencyToken` or a primer-minted token, the client's value is the original. For `[ConcurrencyCheck]` on a column the client edits, the value is data, and treating it as a stamp made every edit a 409. The model cannot tell the two apart, so the write path decides by behaviour:
  - database-generated and marker tokens are stamps up front;
  - a token a prepper moved is a stamp at attach;
  - any other token is decided after the primers, which needs a hook after the primers on every path that runs them.

  A stamp whose new value can equal the old one (a content hash) must be declared with `[VersionStamp]`. Only declared stamps get startup errors; other tokens get Info. A primer that increments a stamp counts from `OriginalValue`. *(2026-09-16)*
- **Pin every `SaveChangesInterceptor` on both `SavingChanges` and `SavingChangesAsync`.** EF calls exactly one of them. The primer, normalizer and auto-truncate interceptors overrode only the async hook, so every synchronous save hard-deleted archivables and skipped stamps, with nothing logged. To bridge async primers into the sync hook:
  - clear `SynchronizationContext`, and start the work on the default scheduler, because a non-default `TaskScheduler.Current` still deadlocks;
  - restore the context before blocking;
  - block with `GetAwaiter().GetResult()`, so callers see the original exception.

  *(2026-09-11)*
- **A `ConcurrentDictionary` reached through `IDictionary` is not a concurrent cache.** The interface leaves only `ContainsKey`-then-`Add`, so two first requests for one entity type raced, and one got "key already existed" out of `SaveChanges`. Declare the concrete type and fill it with `GetOrAdd`. Cold-start faults need tests that exercise first use from several threads; a serial suite cannot reach them. *(2026-09-13)*
- **EF cannot infer an attachment owner's foreign key.** `EntityAttachment` carries the owner's key as `ObjectId`, with no navigation back. Left to conventions, EF maps a shadow `{Owner}Id`, so every link row is saved orphaned. The `/{id}/attachments` routes filter on `ObjectId` and mask it. `AttachmentForeignKeyValidator` reports it at startup. When the pipeline writes one key and the model can map another, validate the model. *(2026-09-21)*
- **`?archived=` lifts only the named filter of the queried `IArchivable` entity.** A filter the app mirrors onto a dependent (`!x.Parent!.IsArchived`) is the app's own, and it is never lifted, so an archived parent's children disappear for everyone. The guides offer the alternative, keeping the parent out of the children's reads. The validator still warns on the mirror. *(2026-09-21)*
- **`SavedChanges` is not the commit.** A single-statement save opens no transaction. A multi-statement save raises `TransactionCommitted` *before* `SavedChanges`. Inside an explicit transaction, the commit comes later. So treat "no current transaction at `SavedChanges`" as committed; otherwise wait for `TransactionCommitted`, keyed on the `DbTransaction`. Contexts sharing a transaction through `UseTransaction` each have their own `TransactionId`, and only the committer raises the event.
  - A transaction disposed without `Commit` or `Rollback` raises neither event, so waiting work sits in a `ConditionalWeakTable`.
  - Npgsql reuses one `NpgsqlTransaction` per pooled connection, so drop waiting work at `TransactionStarted` on that object, never at `TransactionUsed`.
  - An ambient `TransactionScope` is invisible to these events; wait on `Transaction.Current.TransactionCompleted` instead.
  - A rollback to a savepoint cannot be followed.

  *(2026-09-23, keyed on the `DbTransaction` 2026-09-24)*
- **Work deferred to an ambient transaction's completion outlives the scope that queued it.** `TransactionCompleted` fires inside the caller's `Dispose`, possibly after the request scope is gone. Resolve dependencies when the work is queued, and catch everything in the handler, or the caller's `using` throws. Run the work under `TransactionScopeOption.Suppress`. *(2026-09-23)*
- **An entry's `OriginalValues` are what its writer attached, not what the database holds.** `Update(detached)`, a stub `Remove` or `Attach`, and a tracking query leave flags that cannot tell them apart, so only positive evidence counts.
  - `ChangeTracker.Tracked` reports `FromQuery`. Subscribe before the first row materializes (a command interceptor's `ReaderExecuting`), and again on every pool lease.
  - The write path marks what it loads itself. Key the mark on the internal entry (`GetInfrastructure()`), because `ChangeTracker.Clear()` raises no `StateChanged`.
  - `GetDatabaseValues()` reads the stored row and ignores query filters. For many rows, use one no-tracking `IgnoreQueryFilters()` query that projects `EF.Property` of every flattened property and fills a `Clone()` of the originals; EF 8 and 10 both translate nested complex members.
  - Keep the result in your own snapshot, because overwriting `OriginalValues` changes the concurrency `WHERE`.

  *(2026-09-23, positive evidence and batching 2026-09-24)*
- **Turning a delete into an update writes every column unless you unflag them, and unflagging reverts.** `State = Modified` flags every property, and a stub delete's values are empty, so the soft delete overwrote the stored row. `IsModified = false` also resets the current value to the original, so set what you mean to write *after* it. A primer that treats an empty original as "never set" (`Created`) must leave unwritten columns alone. An empty token in the `WHERE` matches nothing. Flags cannot tell a converted delete from a real archiving update, so the archivable primer records the entries it converts and the token primer reads that record. *(2026-09-23)*
- **By the time `SavingChanges` sees a delete, EF has already cascaded it to the loaded dependents.** Under `CascadeTiming.Immediate`, `Remove(parent)` deletes loaded cascading dependents, detaches added ones and nulls optional keys. A loaded `Restrict` dependent throws instead. `Remove` of an untracked parent attaches the graph it carries first.
  - A soft delete must undo the cascade: set deleted dependents back to `Unchanged`, and use `IsModified = false` to restore nulled keys. This also takes back a caller's own `Remove(child)`, since the two look the same.
  - Where the code does the removing, avoid the cascade instead: set `CascadeDeleteTiming = CascadeTiming.OnSaveChanges` around the `Remove`. Changing state inside `StateChanged` stops the cascade only on EF 10.
  - Reset per-pass state when a pass *starts*, because a primer that throws skips the end of its pass.

  *(2026-09-24)*
- **The host serializer decides whether error-body keys are camelCased.** The entity 400 is `BadRequest(ModelState)`, a dictionary. System.Text.Json's `PropertyNamingPolicy` never touches dictionary keys, and its `DictionaryKeyPolicy` is null by default. Newtonsoft's camelCase resolver does rename them. Check a claim about a wire key under the serializer it is about. *(2026-09-27)*
- **A hook that receives a covariant wrapper needs it built for the item's runtime type, because covariance only widens.** Preppers and primers receive the entity itself and cast it, so the service's declared type is enough for them. A validator receives `IEntityValidatorContext<out T>`. A context built over the `Party` a service declares cannot be seen as `IEntityValidatorContext<Person>`, so a validator scoped to the derived type fails its cast. A context built over `Person` serves `Person`, `Party` and `IHasTenantId` alike. The runtime type is known only at run time, which is why there is a cached `MakeGenericMethod(type).CreateDelegate` factory, the same pattern the reactors use for `IEntityChange<out T>`. A typed view wrapped by the base class would avoid reflection, but it works only for `EntityValidatorBase` subclasses; a class implementing `IEntityValidator<T>` directly could not cast what it is given. *(2026-09-30)*
- **A registration that takes `Action<T>` alone turns every `async` lambda into `async void`, and the compiler accepts it.** `e.Validate(async ctx => …)` bound to `Action<IEntityValidatorContext<T>>`. The write stopped waiting at the lambda's first `await`, so an error added after it refused nothing, and an exception after it went unobserved. A `Func<T, Task>` overload beside the `Action` one is source-compatible: C# prefers the `Task`-returning delegate for an async lambda, and a statement lambda without a return still binds to `Action`. Any delegate registration whose body may do I/O needs the `Task` sibling; `Prepare(Action<TEntity>)` has the same shape. Do not add a `Func<T, CancellationToken, Task>` beside a `Func<T, TContext, Task>`. A two-parameter lambda that leaves its second parameter unused fits both and fails with CS0121, and a delegate without DI access has nothing to pass the token to; the `(ctx, db, token)` form covers queries. *(2026-09-30)*
- **Undoing what a refused write marked is not the whole refusal, because the item's own values are the write.** The undo log records the state changes made after it starts. An item the caller loaded with tracking and edited can already be `Modified` when the log begins, or become `Modified` as soon as anything detects its changes. Undoing the log alone therefore let the refused edit reach the caller's next `SaveChanges`. A refusal detaches the item whether or not it was tracked before. Detaching leaves the caller's instance as it was, so a job can fix it and write it again. A `DetectChanges()` before each validated write would also let a refusal revert a prepper's plain edit to another tracked row. It is not run, because it scans every tracked row on every write: that is quadratic across a batch that saves at the end, and every tenant-owned write would pay for it once a global tenant validator exists. A refusal cannot take back that prepper edit, and the docs say so. *(2026-09-30)*
- **A keyed `ServiceDescriptor` reads `null` for its implementation, so the trap is a silent stand-in, not an exception.** `ImplementationType`, `ImplementationInstance` and `ImplementationFactory` threw for a keyed descriptor only in `Microsoft.Extensions.DependencyInjection.Abstractions` 8.0.0. From 8.0.2 they return `null`, and every Regira target resolves 9.0 or later. A scan that filters on `!= null` is therefore already safe, but a `FirstOrDefault`/`LastOrDefault` pick by service type is not. A keyed registration placed last stood in for the one DI resolves, and the validator wiring check went quiet. Pick with `!d.IsKeyedService`. *(2026-09-30)*
- **A validator cannot take an entity service, because every write service imports every validator and the container meets a cycle.** Resolving any `IEntityService<>` builds its write service, which takes `IEnumerable<IEntityValidator>`. A validator that takes `IEntityService<Customer>` needs Customer's write service, which needs the validators again. `GetRequiredService` then throws "A circular dependency was detected" for every entity service in the app, not only the one the validator checks. Use `IEntityReadService<Customer, int>`, the filtered pipeline `Modify` reads its original through; it resolves and applies the same global filters. *(2026-09-30)*

## Security and authentication

- **The auth web base controllers are guarded by default.** The `*ControllerBase<TUser>` types carry no `[Authorize]` by design. The host applies a global requirement (`MapControllers().RequireAuthorization(…)`), so only the `[AllowAnonymous]` actions are public: `POST auth`, `auth/refresh-token`, password recover and reset, and `users/confirm-email`. Do not add class-level `[Authorize]`. Subclasses must not re-declare `[ApiController]` or `[Route]`. The wiring recipe and endpoint tables live in the security hub guide. *(2026-07-02)*
- **When one test assembly hosts several startups, register controllers through an allow-list.** Otherwise every startup discovers every controller, and shared routes (the auth base's in particular) collide. A `ControllerFeatureProvider` that admits only the intended controllers fixes it. *(2026-07-02)*
- **Externally supplied tokens are untrusted input, and their round-trips must be symmetric.** Decode a user-supplied token in a `try/catch` that returns 400. Deserialize it with `System.Text.Json` as the same model it was serialized from; a lenient serializer masks case mismatches, and this also avoids needing an `ISerializer`. A successful authentication resets the access-failed count. *(2026-07-02)*
- **The JWT default, HS512, needs a secret of at least 64 bytes, and registration enforces it.** Without the check, the failure was `IDX10720` as an HTTP 500 at the first login. The rule is algorithm-aware (32, 48 and 64 bytes for HS256, HS384 and HS512). It recognizes both the `HmacSha512Signature` and `"HS512"` spellings and counts `Encoding.ASCII` bytes. It has an opt-out (`ValidateSecretLength`) for schemes that only validate externally signed tokens. *(2026-07-02, enforced 2026-07-30)*
- **`Encoding.ASCII` on the JWT secret is load-bearing; do not "fix" it to UTF-8.** It folds non-ASCII characters to `?`, but widening it derives a different key and signs out every session on deploy. Any change must be opt-in per scheme. `ClockSkew = TimeSpan.Zero` and `ValidateLifetime = LifeSpan > 0` are deliberate too. All three are pinned by characterization tests in `Web.Security.Testing`. *(2026-07-30)*
- **ASP.NET Core 8+ has two inbound claim-type maps, and `AddJwtBearer` uses `JsonWebTokenHandler`'s.** Configuring only `JwtSecurityTokenHandler`'s map is a silent no-op. Do not map `name` or `role` inbound, because `NameClaimType` and `RoleClaimType` hold the JWT spelling. A helper that reads `ClaimTypes.Name` must fall back to the JWT name. Assign these process-global maps; never `Clear()` then `Add()`, which races between hosts. *(2026-07-27)*
- **Authorization applied by `MapControllers().RequireAuthorization()` is invisible to `ActionDescriptor.EndpointMetadata`.** A document generator that reads it describes a guarded API as anonymous. Read `Endpoint.Metadata` instead, matched through `Endpoint.Metadata.GetMetadata<ActionDescriptor>()?.Id`. Also, `new OpenApiSecuritySchemeReference(name)` serializes as an empty object unless it is given the host document. *(2026-07-27)*
- **A policy scheme as the default breaks document generators that read the default scheme.** A policy scheme is registered but only forwards, so no transformer declares it, and every requirement pointed at a missing `securitySchemes` entry. `IAuthenticationSchemeExpander` resolves it to the schemes behind it. It is an optional constructor parameter, so existing registrations keep working. *(2026-07-30)*
- **Each scheme describes itself once.** Every `Add…Authentication` contributes an `ISecuritySchemeDescriptor`, and one transformer maps them all, cross-checked against `GetAllSchemesAsync()`. The descriptor carries no OpenAPI types, because the core package does not reference `Microsoft.OpenApi`. The older per-scheme transformers still work, since everything registers with `TryAdd`. OpenAPI has no cookie type; describe a cookie as an API key `in: cookie`. *(2026-07-30)*
- **A forwarding predicate must test for a usable credential, not a present one.** The chosen handler's `NoResult` ends the request. A blank `X-Api-Key` header must therefore not win over a valid bearer token. Rules are first-match-wins in ascending order, so the strongest credential gets the lowest order. *(2026-07-30)*
- **A scheme selector must never be the fallback for anything that is not credential-driven.** Authenticate and forbid follow the credential; a forbidden caller is authenticated. A challenge and the choice of sign-in scheme cannot, because a browser at a guarded page carries nothing. So challenges forward separately (`ForwardChallenge`, to a registered OIDC scheme). `AddCookieAuthentication` sets `DefaultSignInScheme` and `DefaultSignOutScheme` with `??=`, and the cookie helper uses those, never `DefaultScheme`. *(2026-07-30)*
- **A rule that hardcodes a scheme name works only for the default name.** Each scheme contributes its own forward rule at registration; the selector reads the rules back off `IServiceCollection`, which is sound because it runs last. When a name is configurable, the fixture must use a non-default one and register the selector. *(2026-07-30)*
- **Claim normalization is additive.** `ClaimsNormalizer` adds canonical copies and removes nothing, so a consumer that reads Entra's `roles` keeps working. The copies resolve only because the `ClaimsIdentity` gets the canonical `nameType` and `roleType`. De-duplicate role values, compare claim types case-insensitively, and keep the normalizer idempotent by running it when the ticket is built rather than on every request. Set `MapInboundClaims = false` on schemes you normalize; otherwise `sub` arrives renamed before the normalizer sees it. *(2026-07-30)*
- **Roles, scopes and user ids differ per provider.**
  - Roles arrive as `role`, as Entra's `roles`, or as `ClaimTypes.Role` (the API-key handler and ASP.NET Identity).
  - Scopes arrive as one space-delimited claim, `scp` on Entra and `scope` elsewhere.
  - `FindRoles()` and `HasScope()` handle both.
  - On Entra, `oid` is the stable user id, because `sub` differs per application. `RoleClaimType` must be `"roles"`.
  - Entra issues the audience as either `api://{clientId}` or `{clientId}`, so accept both.
  - A registration with `accessTokenAcceptedVersion: null` issues v1 tokens, which fail with `IDX10205`.
  - `groups` holds GUIDs, and past the size limit it is replaced by `_claim_names`.

  *(2026-07-30)*
- **A multi-tenant Entra API needs an `IssuerValidator`.** With `organizations` or `common` there is no fixed issuer, and the templated `{tenantid}` issuer silently accepts tokens from any directory. Compare the issuer with the token's `tid`, in both the v2 and v1 spellings. Test the positive cases too, because they prove the validator ran. Passing issuer validation is not tenant authorization. *(2026-07-30)*
- **Apply defaults before a customization hook, and invariants after it.** The Entra presets first set the multi-tenant `IssuerValidator` before `Configure`, so a consumer who replaced `TokenValidationParameters` lost it. The same applies to chaining `OnTokenValidated` after the consumer's `Events`. Tests replace the parameters from `Configure` and assert that the validator survived. *(2026-07-30)*
- **Either wire a customization point fully or do not expose it.** The Entra preset copied only `RoleClaimTypes` from its `ClaimNormalizationOptions` and silently ignored the rest. `MergeInto` on the options object replaces field-by-field copies, which drift. *(2026-07-30)*
- **Options registered as bare singletons make "which one" unanswerable.** `AddOidcAuthentication` registers a cookie scheme of its own, so a second `CookieAuthOptions` made sign-in pick whichever was registered last. Options are now keyed by scheme (`AddKeyedSingleton`), and the default resolves from `AuthenticationOptions`, as `SignInAsync(null, …)` does. A second `AddSchemeSelector` throws at registration. *(2026-07-30)*
- **OIDC interactive sign-in is a pair of schemes.** The cookie is the default, authenticate and sign-in scheme; OIDC is the challenge and sign-out scheme. Sign-out needs both halves, or the provider silently signs the user back in. Behind a TLS-terminating proxy, `UseForwardedHeaders` must run before authentication, or the callback fails with "Correlation failed". *(2026-07-30)*
- **A secure-by-default cookie is invisible over plain HTTP.** With `CookieSecurePolicy.Always`, sign-in succeeds and every later request is anonymous (401), with nothing logged. Test over `https://localhost`, since `TestServer` honours the scheme, rather than weakening the policy. *(2026-07-30)*
- **Cookie auth in an API overrides the redirect events.** Clearing `LoginPath` only redirects to a built-in default. Replace `OnRedirectToLogin` and `OnRedirectToAccessDenied` with 401 and 403 writes; otherwise `fetch` follows the 302 into an HTML page, and cross-origin it surfaces as an opaque CORS error. The constants are named `CookieAuthDefaults`, because the framework owns `CookieAuthenticationDefaults`. *(2026-07-30)*
- **`auth/refresh` is a sliding renewal, not a refresh-token flow.** It needs a still-valid access token. The anonymous `auth/refresh-token` takes the refresh token itself as its credential. Both endpoints stay, because the old one picks up role changes. Adding the new one to a shipped base stayed compatible:
  - `IRefreshTokenService` is resolved from `RequestServices`, so no constructor changes;
  - an unregistered service answers 404;
  - new DTO fields are `[JsonIgnore(WhenWritingNull)]`, so an opted-out host's responses stay byte-identical.

  *(2026-07-30)*
- **Refresh-token rotation must revoke the whole family on replay, atomically.** A second presentation of a rotated token proves that two parties hold it, so end the chain.
  - `RevokeFamily` also reaches already-revoked tokens.
  - An absolute ceiling bounds how long a chain can live.
  - A required claims resolver re-reads roles and account state on each refresh.
  - The revoke is a test-and-set (`IRefreshTokenStore.TryRevoke`, a conditional write that returns `bool`), claimed before anything is issued. Otherwise two concurrent refreshes (a SPA after one 401) fork the family undetected.

  An extension point's shape decides whether consumers *can* implement it correctly. *(2026-07-30)*
- **Hash refresh tokens unsalted, unlike passwords.** Lookup is by hash, and a 256-bit random token has nothing guessable to protect. `IHasher`'s salt and iterations are for passwords. The in-memory store is for development only: it loses sessions on restart and is per-process behind a load balancer, and neither failure shows on one machine. *(2026-07-30)*
- **A content type a client can set is a page it can serve from your origin, so trace every writer of it.** Uploads took the browser's declared type, and `NewContentType` let a JSON update retype a stored file: a `.png` holding `<script>` then rendered inline as `text/html`, and the blob store served it the same way once `Save` honoured its argument. Fixing the upload left the JSON path open. Type a file by its name wherever it is stored, and send `Content-Security-Policy: sandbox` with every file but a PDF, whose viewer a sandbox keeps from loading: a list of the types that render as a page misses some, such as `text/xsl`. *(2026-09-30)*

## Office, IO and packaging

- **NuGet `contentFiles` never reach a transitive consumer.** A package that wraps a backend with a native or data companion (`PDF.SelectPdf`'s `Select.Html.dep`, `OCR.Tesseract`'s `tessdata`) ships a `buildTransitive` targets file. That file copies the companion from the restored package into `$(OutDir)` and the publish output. MSBuild evaluates a target's `Condition` before its `DependsOnTargets`, so put item checks on the task. Compose paths with `EnsureTrailingSlash($(NuGetPackageRoot))`. Verify with a throwaway consumer and `NUGET_PACKAGES` pointed at a scratch folder, because the global cache never re-extracts a same-version package. *(2026-08-05)*
- **Read an `IMemoryFile` with `GetBytes()`, never `.Bytes`.** A producer fills either `Bytes` or `Stream`, and which one depends on the method, not the backend: `PDF.DocNET` mixes both, and the `IHtmlToPdfService` backends differ. `.Bytes` on a stream-built file gives a 200 with an empty body. `GetBytes()` (`Regira.IO.Extensions`, in `Regira.Common`) handles both. *(2026-08-05)*
- **The Office backends take their configuration through the constructor and ship no DI extension.** An extension that registers only `IWordService` fails consumers who resolve the narrow interfaces. One that registers all of them joins a last-wins contest with every other backend. `Word.Gotenberg` keeps its extension, because a named `HttpClient` needs the factory. *(2026-09-16)*
- **`AddHttpClient<TClient, TImplementation>()` names the client after `TClient`.** Two packages registering `IWordConverter` shared one client and ran both configure actions, sending credentials to the other server. Give each package's client its own name: `AddHttpClient(name, configure).AddTypedClient<TInterface, TImplementation>()`. *(2026-09-16)*
- **A licence check is evidence only once its unlicensed sibling fails.** Syncfusion and Aspose degrade instead of failing: they add banners, and Aspose truncates after a few hundred paragraphs. Content assertions therefore pass on evaluation output.
  - `AsposeEvaluationTests` runs unlicensed and asserts the check fails. It is gated on the same environment variables in the opposite direction, because the licence is process-global.
  - Apply a configured licence in the fixture constructor, so a bad licence fails loudly.
  - Aspose's evaluation mode also rewrites the headers and footers of every document it *loads*, so header and footer behaviour can be tested on Aspose only with a licence.

  *(2026-09-16)*
- **Aspose.Words `Range.Replace` reads `&p`, `&l`, `&m` and `&b` in the replacement as breaks, with a `Regex` pattern too.** Escape `&` as `&&` in every replacement built from caller data. *(2026-09-16)*
- **Read a vendor assembly's API with `MetadataLoadContext`.** `Assembly.LoadFrom` fails when a signature's dependencies are missing. Vendor XML docs list internal members; Syncfusion's lists a `WordDocument.DifferentOddAndEvenPages` that does not compile. Treat those docs as a lead, not a signature. A console tool with a `PathAssemblyResolver` prints public signatures, enum members and interfaces. *(2026-09-16)*
- **Bound recursion per call, not per instance.** An instance counter (`_insertDocumentCounter`) was a lifetime limit: it wore out singletons and raced across threads. An `AsyncLocal<int>` depth around the method every recursion passes through (the document build) stops cycles and never wears out. Test one instance past the limit. *(2026-09-16)*
- **MiniWord matches a tag only when it sits whole in one run and reads exactly `{{key}}`.** Its pattern is `{{(\w+(\.\w+)*)}}`, and it does not merge runs. Before MiniWord reads the template, rewrite each paragraph over its concatenated `w:t` text, moving a split tag into the element it starts in. *(2026-09-16)*
- **First-page and odd/even flags switch headers and footers together.** Adding an `Even` header leaves even pages without a footer, unless the footer also gets default content for that version. Only a rendered, per-page check catches it. *(2026-09-16)*
- **FreeSpire.Doc's free edition caps PDF output at three pages.** It adds a vendor notice page and throws nothing. Page images and the other formats keep every page. This is in addition to the 500-paragraph and 25-table caps. *(2026-09-27, FreeSpire.Doc 14.4.0)*
- **Word template features use Regira's own markers, not a vendor's.** No backend evaluates Word IF fields on `Create`, Spire does not substitute inside field codes, Aspose's `<<if>>` exists on Aspose alone, and MiniWord's `@if` compares a bool as text. So the syntax and the decision live once in `Common.Office` (`Word/Templating`). Each backend maps its containers' children to texts and removes the indices it gets back. Two traps in the removal: a table cell must keep a closing paragraph, and in raw Open XML a paragraph that carries `w:sectPr` is a section break. That paragraph is emptied rather than removed, and blocks are resolved per section. *(2026-09-27)*
- **The Word backends bind to `Regira.Office` internals, so changing those internals means publishing the Word family together.** `ConditionalBlocks`, `VisibleText` and `WordContentTypes` are `internal` in `Regira.Office`. Word.Spire, Word.Syncfusion, Word.Aspose, Word.Mini and Word.Gotenberg reach them through `InternalsVisibleTo`. NuGet resolves a Word backend against any `Regira.Office` at or above its floor, and internals carry no compatibility promise. A later `Regira.Office` that renames or reshapes one leaves an older Word backend failing at run time with `MissingMethodException`, not at restore. The aligned whole-family publish keeps them matched, and a change to those internal signatures has to ship every Word backend on the same number. *(2026-09-30)*
- **A regex over document or request text is an attack surface, so build it with `RegexOptions.NonBacktracking`.** The Word `{{#if}}` marker pattern had two optional white-space runs around an optional `!` and a lazy key. A paragraph of `{{#if`, twenty thousand spaces and `}}` took 3.3 s, and the test runs on every paragraph of every `Create`, `Convert` and `GetText`, including the in-process scan of every Gotenberg upload. `NonBacktracking` made it linear with the same captures; it rules out only lookarounds, backreferences and atomic groups. Pin it with a test on a long run of spaces. *(2026-09-30)*
- **A template engine's output can be a template again.** Word blocks are resolved before parameters are filled, so `Create` is safe, but a value that fills a paragraph with a lone `{{#if X}}` makes the output use blocks: a later `GetText` or `Convert` of it throws, or drops what two such values enclose. Convert in the call that fills, or keep user values out of paragraphs of their own. *(2026-09-30)*

## System and database backups

- **`IProcessHelper.ExecuteCommand` writes the command to a temporary `.bat`, which makes it wrong for secrets or `%`.** The arguments sit on disk, and cmd expands `%…%` even inside quotes.
  - `ExecuteFile(filename, waitForOutput, arguments)` starts the executable directly, with no file and no shell.
  - A secret belongs in the process environment, never in the command text. The overload that takes variables is a default interface method, and it sets them in the script rather than dropping them.
  - `waitForOutput` defaults to false, which leaves `Error` null in failure messages, so turn it on. Since `Regira.System` 6.3.0, both streams are drained concurrently.
  - `ExecuteCommand` writes `@echo off`, so captured output does not echo the script's lines.
  - `pg_dump` reads `PGPASSWORD`. `mongodump` and `mongorestore` read no variable and prompt on the console, so their only channel off the command line is a `--config` YAML file (Database Tools 100.3.0+).

  *(2026-09-12)*
- **`pg_dump --schema` takes a pattern, not a name.** Unquoted names fold to lower case, and `*`, `?` and `.` act as wildcards and separators. A pattern that matches nothing is skipped and the dump still exits 0. Pass `"Sales"` with embedded quotes doubled, and add `--strict-names`. *(2026-09-16)*
- **The MongoDB tools' `--config` file must carry the URI as well as the password.** TLS key passwords and `AWS_SESSION_TOKEN` are connection-string options, so a URI on the command line leaks them. A username without a password makes the tools prompt, and a redirected stdin cannot answer. Refuse that up front, except for mechanisms that take no password. *(2026-09-16)*
- **`RESTORE … WITH REPLACE` silently overwrites an offline database's files.** Compare the planned physical names with `sys.master_files` first. Use `REPLACE` only when the target database existed. *(2026-09-16)*
- **Use `sys.xp_delete_files` (SQL Server 2019+), because `xp_delete_file` refuses current backups.** Both need `sysadmin`, so cleanup is best effort with a logged fallback. Guard on `OBJECT_ID(N'master.sys.xp_delete_files')`, and read the outcome back with `xp_fileexist` rather than trusting "no error". *(2026-09-16)*
- **Take a database away with `SET OFFLINE`, not `SINGLE_USER` then `DROP`.** `SINGLE_USER WITH ROLLBACK IMMEDIATE` leaves the one session free for anyone between the two statements. The cost of `OFFLINE`: SQL Server keeps an offline database's files when it drops it. A restore `WITH REPLACE` to the same paths overwrites them, and other files stay on disk. *(2026-09-16)*

## Other packages

- **TreeList: three defects where the README was right and the code was silently wrong.**
  1. A parents-selector `Fill` walks down from the values with no parent, so cycles and values whose parent is missing were never visited and `ThrowOnError` could not fire. A reached-set check now runs after every fill. A node count proves nothing, because a value with several parents takes several nodes.
  2. Under `ThrowOnError = false`, `AddChild` must use `FirstOrDefault`, and the recursive walker needs a null guard.
  3. Ordering a hierarchy is per-level recursion. Sorting a flattened subtree breaks the parent-before-child guarantee.

  *(2026-08-27)*
- **Bot detection: first require the shape every browser shares, then classify on what a forger cannot control.**
  - A deny-list of crawler names missed 18 of 48 crawlers in one day. `RequireBrowserToken` closed the gap: every browser announces `Mozilla/` or `Opera/`. The list now only has to catch crawlers that wear a browser string.
  - An exception to a broad marker cancels only the marker it overlaps. Drop markers that match in-app browsers (`pinterest`).
  - A scanner behind a copied Chrome string is caught by its target instead. `BotDetector.IsProbe(path, queryString)` flags known sweep paths, dot-directories and paths that climb out of the site root. Only add rules that no real page can match: `/wp-admin` is safe, `/admin` never is.

  *(2026-09-05)*
